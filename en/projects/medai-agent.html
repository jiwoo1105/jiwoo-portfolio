MedAI Agent

Organizing medication information into a staged reporting workflow.

Medication-information analysis prototype
My focus
Input, medication lookup, agent orchestration, and results interface
When
2025 · Deep learning project
The problemWorkflowInterfaceScope of validation

The problem

One workflow for different input methods.

This prototype organizes medication names and question context from text, voice, or image inputs and presents the output as a readable report. It connects the input interface, an external medication-information API, LLM processing, and the results UI.

Workflow

Connecting eight stages with distinct roles.

The sequence covers input understanding, medication recognition, background knowledge, detailed analysis, side-effect review, evidence explanation, context-specific information, and report generation. Outputs pass between stages and are collected into a summary, key findings, and cautions.

The eight agents are LLM processing stages assigned different roles; they are not eight independent medical experts. Information retrieved from the MFDS medication API must also be distinguished from explanations generated by the LLM.

Interface

Designing both progress feedback and the final report.

The React interface supports text, voice, and image input and displays progress through the processing stages. FastAPI responses are organized into a summary, a risk indicator, and detailed explanations. The project explores how to present a workflow that involves multiple model calls.

Scope of validation

A working prototype is not clinical validation.

The public demo shows the path from input to the results screen. Risk scores and recommendations are model-generated reference information, not clinically validated probabilities or prescribing decisions.

Further evaluation should cover medication-name recognition errors, missing source information, unsupported explanations, and error propagation between stages. Each stage’s contribution to output quality needs to be measured.
