문제

질문에 충분히 답하고, 끝까지 응답하게 만들기.

해커톤에서 제공한 L2-preview 모델을 활용해 의료 질의응답 시스템을 개발했습니다. 제한된 시간 안에 사용자의 여러 요구를 빠짐없이 다루고, 필요한 근거와 주의사항을 포함하며, 최종 응답이 잘리거나 비지 않도록 만드는 것이 과제였습니다.

모델 가중치를 학습하는 대신 호출 전후의 처리를 개선했습니다. 저는 MCP 검색과 생성의 연결, 약물 안전 게이트, 근거에 없는 인용과 검색 중복 점검, 멀티턴 응답 보강에 참여했습니다.

근거 연결

질문마다 필요한 근거의 범위를 다르게 봤습니다.

초기에는 분류·검색·생성을 연결하는 다단계 경로를 구현했습니다. 이후 팀은 직접 생성 경로를 기본으로 두고, 약가·허가·적응증·의료 코드처럼 공식 데이터가 명확하게 필요한 질문에 MCP 조회를 선택적으로 적용하는 방향으로 발전시켰습니다.

검색을 더 많이 수행하는 것 자체를 개선으로 간주하지 않았습니다. 조회 실패나 모호한 대상, 검색 중복을 점검하고, 확보한 근거에 없는 수치나 인용을 답변에 추가하지 않도록 흐름을 다듬었습니다.

추론 흐름

문맥, 시간, 출력 길이를 함께 관리했습니다.

최신 사용자 메시지의 답변 지시를 보강하면서 이전 대화 이력을 유지했습니다. 필요한 검사 결과나 약물 목록을 확인하고, 질문의 일부만 답하거나 진료 권유만으로 끝나는 응답을 줄이는 방향을 실험했습니다.

팀의 현재 실행 구조는 토큰·시간 예산, 잘림·빈 응답 시 재시도, 결함이 의심되는 출력에만 추가 검증을 수행하는 처리를 포함합니다. 저는 개인 커밋의 구현 범위와 팀이 함께 발전시킨 최종 시스템을 구분해 기록했습니다.

팀 성과

벤치마크 1위, AIM 팀 공동 수상.

AIM 팀은 루닛 Conquer Health 해커톤에서 HealthBench 기반 평가 최고점으로 벤치마크상을 받았습니다. 아래 상장은 팀 공동 수상에 대한 공식 증빙입니다.

팀의 공개 최종 평가 기록에는 3라운드 평균 46.51점과 최종 평가 참여 14개 팀 중 1위가 기재돼 있습니다. 상장 자체에는 점수가 없으므로 수상 증빙과 팀의 점수 기록을 구분합니다.

판단과 한계

각 변경의 효과는 별도의 검증이 필요합니다.

개발 중 비교한 생성 경로의 점수나 특정 프롬프트의 관찰 결과를 공식 최종 점수와 섞지 않았습니다. 멀티턴 문구 보강만의 점수 효과도 분리해 검증된 값은 아닙니다. 이 경험을 통해 도구 연결뿐 아니라 답변의 완결성과 평가 조건을 함께 설계하는 법을 배웠습니다.

대회 벤치마크 결과이며 실제 환자를 대상으로 한 임상 성능 검증은 아닙니다.
