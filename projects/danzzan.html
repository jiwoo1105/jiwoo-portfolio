배경과 역할

몰리는 요청과 계속 바뀌는 운영 조건을 함께 다뤘습니다.

학생에게 흩어진 부스 정보, 공연 일정, 공지와 예매를 한곳에서 제공하고 운영진이 현장 상황을 반영할 수 있도록 만든 팀 서비스입니다. 한정된 티켓의 중복 발급을 막는 일과 예매·입장 상태를 사용자에게 정확히 보여주는 일이 핵심 과제였습니다.

저는 Redis 대기열과 Lua 발급 처리, JWT 로그인·회원가입, 번역 기능과 실패 대응을 맡았습니다. 6,000명 이상의 실사용자와 두 차례 축제 운영은 팀 공동 성과입니다. 봄에는 예매·입장 흐름을, 가을에는 다국어 사용성을 개선했습니다.

동시 요청 처리

대기열을 상태 전이와 재고 정합성 문제로 풀었습니다.

대기·입장 준비·예매 가능·완료·만료 상태를 구분하고, Lua Script로 입장 자격·중복 신청·남은 재고 확인과 차감을 한 번에 처리했습니다. 이 원자성은 Redis 내부의 작업에 해당하며 MySQL까지 포함하는 분산 트랜잭션을 뜻하지 않습니다.

단순히 성공 응답을 반환하는 것보다, 중간 단계에서 멈췄을 때 사용자가 어떤 상태인지 설명하는 데 집중했습니다. 빈 대기열, 비동기 예매 진행 중, 입장 만료와 예매 오픈 전 오류를 구분하도록 개선했습니다. Kafka·DB 비동기 처리에는 다른 팀원의 기여가 포함됩니다.

  1. 신청 자격 확인

    대기열·예매 시간·입장 유효성

  2. Redis 원자 처리

    중복 확인·재고 검사·차감

  3. 상태·복구 안내

    진행 중·완료·만료·실패를 구분

운영 개선

실패한 뒤에도 다시 시도할 수 있는 서비스로.

만료된 토큰이 로그인 요청에 붙으면 인증 필터에서 401이 발생해 다시 로그인할 수 없는 문제가 있었습니다. 로그인·토큰 재발급 등 공개 경로를 JWT 인증 필터의 검사 대상에서 제외해 인증 복구 흐름을 바로잡았습니다.

번역 API 실패가 공지 등록 실패로 이어지지 않도록 예외를 처리했습니다. 콘텐츠 저장 시 번역을 보관하고, 영어가 없으면 한국어를 제공하며, 누락된 영문은 나중에 보충하는 흐름을 구현했습니다. 이미 작성된 번역은 보존합니다.

예매 시간·수량·공연일을 관리자와 사용자 화면에 연결하고, 시작된 회차의 수정 제한과 티켓팅 ON/OFF 정책을 정리했습니다. 운영자가 직접 바꿀 수 있는 범위를 늘리는 방향으로 개선했습니다.

협업

총학생회·네이버와 이어지는 현장 입장 흐름.

총학생회와 협업한 축제 운영에 네이버 Face Sign 연계 입장 흐름을 적용했습니다. 단짠은 티켓 예매, 제3자 제공 동의와 사전 등록 안내를 담당하고, 얼굴 정보 등록과 인증은 네이버가 처리합니다. 얼굴인식 모델 자체를 개발한 프로젝트는 아닙니다.

예매 완료와 얼굴 등록 완료가 다른 단계임을 안내하고, 사용자 요구를 후속 다국어 기능에 반영했습니다. 대외 협업·행사 운영·프론트엔드·Kafka/DB 비동기 처리에는 팀원의 기여가 포함됩니다. 제 개인 기여는 예매·인증·번역의 백엔드 처리입니다.

일정과 협업

마감일만 공유하던 방식을, 진행 상황을 함께 보는 방식으로 바꿨습니다.

작업 지연이 반복될 때 Jira로 작업을 작게 나누고, 스프린트와 데일리 스크럼으로 진행 상황과 막힌 부분을 공유하도록 했습니다. 이후 티켓팅 일정이 앞당겨지자 남은 작업과 우선순위를 다시 정리했고, 팀은 변경된 기한 안에 개발을 마쳤습니다.

배운 점

운영자가 쓰는 순간까지가 개발의 범위였습니다.

요청을 빠르게 받는 것뿐 아니라 중간 단계에서 실패했을 때 사용자가 어디로 돌아갈지, 운영자가 무엇을 바꿀 수 있는지까지 정해야 했습니다. 예매 상태·인증 복구·번역 실패를 각각 다루면서 기능의 성공 경로와 복구 경로를 함께 설계하는 습관을 얻었습니다.

프로젝트 활동 기간은 2025년 12월부터 2026년 9월까지입니다. 운영 당시 팀 성과와 개인 구현 범위를 구분해 기록했습니다.

후속 테마 작업을 기존 축제 운영 성과나 이미 배포된 기능으로 합산하지 않습니다.
